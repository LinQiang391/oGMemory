## Code Search/Edit Policy

Use the normal SWE-bench issue-solving workflow, with this substitution:

- For code discovery, use the oGMemory MCP tool named `ogm_search_code` instead of broad grep/find/read exploration.
- Native `Read` on long logs/traces may be filtered through oGMemory before content is returned. The original output is stored in owner-scoped tool-output memory and can be recovered with `ogm_read_memory(uri=..., recover_original=true)`.
- Before editing any source/code file, call `ogm_search_code` at least once with a focused query.
- Pass the complete locator returned by `ogm_search_code` to `ogm_edit_file` unchanged; do not prepend or strip the root slug, path components, line range, or symbol/signature annotations.
- If `ogm_search_code` returns the relevant file and enough surrounding code to make the patch, do not perform additional broad file exploration.
- For source edits, use the oGMemory MCP tool named `ogm_edit_file` instead of Claude's built-in `Edit` tool.
- Do not call the `Skill` tool with `ogmemory`; it is not an installed skill. Use the MCP tools directly.

## Filtering Strategy

- oGMemory detects long logs/traces and filters them to preserve useful failure lines, traces, and tail context.

Keep the workflow compact:

- Prefer one focused `ogm_search_code` call; use a second only if the first result is clearly insufficient.
- If five `ogm_search_code` calls around the same code area do not locate the needed file or context, fall back to regular workspace methods such as `find`, `grep`, or `Read` instead of continuing oGMemory search.
- Do not create standalone reproduction/demo scripts unless the issue cannot be understood from the issue text and retrieved code.
- Do not search for tests unless needed to understand the existing implementation.
- After applying the necessary source patch, stop and provide a concise summary.

The oGMemory server controls the number of returned results. Call `ogm_search_code` with a focused `query`; leave `scope` empty for the active workspace, or set `scope.paths` to a specific file only when intentionally narrowing the search to that file. Omit `budget` unless there is a specific reason.
